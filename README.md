## معرفی

این سامانه به تیم‌های دفتر فنی کمک می‌کند تا:

- صورتجلسات را ثبت و بایگانی کنند
- مهلت انجام و تأخیرها را ببینند
- گردش کار داخلی (کارفرما → دفتر فنی → کارشناس → مدیر سایت → ابلاغ) را پیگیری کنند
- مسیر واقعی **پیمانکار → نظارت → کارفرما** را با تاریخ ثبت کنند
- مدارک اسکن‌شده را از پوشه شبکه پیدا و باز کنند
- گزارش HTML و خروجی اکسل بگیرند

رابط کاربری راست‌به‌چپ (RTL) و تاریخ‌ها به‌صورت شمسی (جلالی) نمایش داده می‌شوند.

## قابلیت‌های اصلی

| حوزه | توضیح |
|------|--------|
| **ثبت صورتجلسه** | شماره، موضوع، تاریخ‌ها، کارفرما/مشاور/پیمانکار، دیسیپلین، محل کار، اولویت |
| **مسیر نظارت** | تاریخ ارسال به نظارت، ورود به دفتر نظارت، ورود به کارفرما |
| **گردش کار ۶ مرحله‌ای** | دریافت کارفرما → ارجاع دفتر فنی → بررسی کارشناس → تأیید دفتر فنی → تأیید مدیر سایت → ابلاغ به پیمانکار |
| **ابلاغ = اتمام** | ثبت تاریخ ارسال به پیمانکار پرونده را تکمیل‌شده می‌کند |
| **هشدار شباهت** | جلوگیری نسبی از ثبت تکراری همان کار توسط پیمانکار (محل / نقشه) |
| **فیلتر شماره** | جستجوی حاوی (مثلاً `10`) + گزارش HTML |
| **اسکن شبکه** | پیدا کردن PDF/تصویر با نام برابر شماره صورتجلسه |
| **نقش و دسترسی** | admin / manager / editor / user / viewer |
| **حذف منطقی** | Soft-delete با حفظ سابقه |
| **لاگ ممیزی** | ثبت رویدادهای مهم (از جمله عبور از هشدار شباهت) |

## جریان کاری

### مسیر واقعی سند

```
پیمانکار  ──ارسال──►  نظارت  ──تأیید──►  کارفرما  ──گردش داخلی──►  ابلاغ به پیمانکار
              │                │              │
       ارسال به نظارت   ورود به نظارت   ورود به کارفرما
```

### مراحل گردش کار داخلی (صورتجلسات جدید)

1. ثبت و دریافت صورتجلسه در دفتر کارفرما  
2. ارجاع پرونده به رئیس دفتر فنی  
3. بررسی فنی و ثبت نظر کارشناس  
4. کنترل و تأیید رئیس دفتر فنی  
5. تأیید نهایی مدیر سایت  
6. ابلاغ رسمی به پیمانکار و بستن پرونده  

### وضعیت‌ها

`در دست بررسی` · `در انتظار تأیید` · `تکمیل شده` · `لغو شده` · `بازگشت داده شده`

## نصب و اجرا

### پیش‌نیاز

- Python **3.11+**
- ویندوز (پیشنهادی برای محیط دفتر) یا لینوکس/مک برای توسعه

### نصب وابستگی‌ها

```bash
git clone https://github.com/Tahmoures54/Document-Tracking.git
cd Document-Tracking
pip install -r requirements.txt
```

### اجرا

```bash
python app.py
```

برای دیتابیس مشترک شبکه، طبق بخش «دیتابیس مشترک شبکه (چندکاربره)» از URL اتصال PostgreSQL با گزینه `--db-url` استفاده کنید. مسیر فایل SQLite فقط برای دیتابیس محلی است.

## ساخت فایل اجرایی (EXE)

### الف) از GitHub Actions (پیشنهادی)

1. مخزن → **Actions** → **Build Windows Executable**
2. **Run workflow**
3. دانلود Artifact به نام `DocumentTracking-Windows`

با زدن تگ نسخه، Release هم ساخته می‌شود:

```bash
git tag v3.1.0
git push origin v3.1.0
```

### ب) ساخت محلی

```bash
pip install -r requirements.txt
pyinstaller build.spec
# خروجی: dist/DocumentTracking.exe
```

یا همان دستور کامل داخل ورک‌فلو (بدون کنسول، با آیکون `app.ico`).

## دیتابیس مشترک شبکه (SQLite)

طبق سناریوی ساده و کم‌هزینه، برنامه روی هر رایانه جداگانه نصب می‌شود و همه همکاران یک فایل SQLite مشترک روی پوشه شبکه را باز می‌کنند.

### راه‌اندازی
1. روی رایانه‌ای که همیشه روشن است، پوشه‌ای مانند D:\\DocumentTrackingData بسازید و آن را با نامی مانند DocumentTracking در شبکه Share کنید.
2. برای کاربران موردنظر مجوز خواندن، نوشتن، تغییر و حذف فایل را در هر دو سطح Share و Security/NTFS تعریف کنید. کاربران باید بتوانند فایل‌های جانبی دیتابیس را نیز ایجاد کنند.
3. روی هر رایانه برنامه را نصب و با همان مسیر UNC اجرا کنید. مثال:

    DocumentTracking.exe --db "\\\\OFFICE-SERVER\\DocumentTracking\\meetings.db"

یا در اجرای نسخه پایتونی:

    python app.py --db "\\\\OFFICE-SERVER\\DocumentTracking\\meetings.db"

به‌جای OFFICE-SERVER نام رایانه میزبان و به‌جای DocumentTracking نام Share خودتان را قرار دهید. از مسیر UNC استفاده کنید، نه درایو شبکه‌ای مثل Z:\؛ چون حرف درایو ممکن است بین کاربران متفاوت باشد. مسیر در هر رایانه ذخیره می‌شود.

### نکات مهم پایداری
- تنظیمات SQLite به حالت DELETE تغییر کرده است و دیگر WAL فعال نمی‌شود؛ برای این روش فایل‌های جانبی WAL ایجاد نمی‌شوند.
- برنامه برای قفل دیتابیس تا ۳۰ ثانیه منتظر می‌ماند. اگر کاربری در حال ذخیره‌سازی باشد، همکار دیگر ممکن است برای نوشتن منتظر بماند.
- **این روش برای دفتر کوچک با حجم نوشتن کم مناسب‌تر است؛ SQLite روی پوشه شبکه یک سرور دیتابیس واقعی نیست.** قطعی شبکه، خاموش‌شدن ناگهانی میزبان یا فایل‌سیستم ناسازگار می‌تواند باعث خطا یا آسیب به دیتابیس شود. تعداد زیادی عملیات نوشتن هم‌زمان را روی این معماری قرار ندهید.
- قبل از شروع کار، از دیتابیس فعلی نسخه پشتیبان بگیرید. پشتیبان‌گیری را وقتی برنامه‌ها بسته‌اند انجام دهید یا از ابزار بکاپ سازگار با SQLite استفاده کنید.
- همه رایانه‌ها باید به همان فایل دقیق وصل شوند؛ اجرای برنامه بدون گزینه --db از دیتابیس محلی همان رایانه استفاده می‌کند و داده‌هایش مشترک نخواهد بود.
- حساب ورود برنامه و نقش‌های فعلی برای ثبت هویت تغییرات حفظ شده‌اند؛ مجوزهای پوشه شبکه نیز باید درست تنظیم شوند.
- در دیتابیس تازه، حساب پیش‌فرض admin/admin ایجاد می‌شود؛ رمز را بلافاصله عوض کنید. فایل دیتابیس قبلی خودکار به مسیر جدید منتقل نمی‌شود؛ فایل موجود را با برنامه بسته‌شده کپی کنید و پیش از استفاده، نسخه پشتیبان نگه دارید.

## اسکن مدارک

مسیر پیش‌فرض شبکه:

```text
\\192.168.200.6\technical office\_MOM\_Scan
```

قابل تغییر با:

- متغیر محیطی `MOM_SCAN_PATH`
- یا تنظیمات داخل برنامه (`get_scan_path()`)

پسوندهای پشتیبانی‌شده: `.pdf` `.png` `.jpg` `.jpeg` `.tif` `.tiff`

نام فایل باید با **شماره صورتجلسه** یکی باشد؛ مثال: صورتجلسه `1404-025` → فایل `1404-025.pdf`

## گزارش‌ها

| نوع | نحوه |
|-----|------|
| گزارش گردش کار یک پرونده | از دیالوگ گردش کار |
| گزارش فیلتر شماره صورتجلسه | فیلد «شماره صورتجلسه» + دکمه **گزارش شماره** |
| خروجی اکسل | دکمه خروجی در پنجره اصلی |
| نمودار آماری | دکمه نمودار (در صورت نصب matplotlib) |

گزارش شماره شامل: **محل کار**، **روز مانده تا مهلت**، **موضوع**، **پیمانکار** و خلاصه بر اساس موقعیت است و به‌صورت HTML در پوشه `reports` ذخیره می‌شود.

## تست

```bash
pip install pytest
pytest
```

پوشش فعلی (حداقلی و هدفمند):

- منطق تأخیر و ابلاغ مدل `Meeting`
- اعتبارسنجی فیلدهای اجباری
- جستجوی حاوی شماره صورتجلسه
- هشدار شباهت پیمانکار + محل
- ساخت خودکار ۶ مرحله گردش کار
- صحت دیتابیس محلی و تنظیمات SQLite
- تهیه بکاپ سالم و جلوگیری از بازنویسی دیتابیس زنده
- گزارش HTML جزئی و تجمیعی مدت رسیدگی هر مرحله
- هش رمز عبور PBKDF2، پشتیبانی از هش‌های قدیمی و ارتقای خودکار پس از ورود موفق
