## معرفی

این سامانه به تیم‌های دفتر فنی کمک می‌کند تا:

- صورتجلسات را ثبت و بایگانی کنند
- مهلت انجام و تأخیرها را ببینند
- گردش کار داخلی (کارفرما → دفتر فنی → کارشناس → مدیر سایت → ابلاغ) را پیگیری کنند
- مسیر واقعی **پیمانکار → نظارت → کارفرما** را با تاریخ ثبت کنند
- مدارک اسکن‌شده را از پوشه شبکه پیدا و باز کنند
- گزارش HTML و خروجی اکسل بگیرند

رابط کاربری راست‌به‌چپ (RTL) و تاریخ‌ها به‌صورت شمسی (جلالی) نمایش داده می‌شوند.

## قابلیت‌های اصلی

| حوزه | توضیح |
|------|--------|
| **ثبت صورتجلسه** | شماره، موضوع، تاریخ‌ها، کارفرما/مشاور/پیمانکار، دیسیپلین، محل کار، اولویت |
| **مسیر نظارت** | تاریخ ارسال به نظارت، ورود به دفتر نظارت، ورود به کارفرما |
| **گردش کار ۶ مرحله‌ای** | دریافت کارفرما → ارجاع دفتر فنی → بررسی کارشناس → تأیید دفتر فنی → تأیید مدیر سایت → ابلاغ به پیمانکار |
| **ابلاغ = اتمام** | ثبت تاریخ ارسال به پیمانکار پرونده را تکمیل‌شده می‌کند |
| **هشدار شباهت** | جلوگیری نسبی از ثبت تکراری همان کار توسط پیمانکار (محل / نقشه) |
| **فیلتر شماره** | جستجوی حاوی (مثلاً `10`) + گزارش HTML |
| **اسکن شبکه** | پیدا کردن PDF/تصویر با نام برابر شماره صورتجلسه |
| **نقش و دسترسی** | admin / manager / editor / user / viewer |
| **حذف منطقی** | Soft-delete با حفظ سابقه |
| **لاگ ممیزی** | ثبت رویدادهای مهم (از جمله عبور از هشدار شباهت) |

## جریان کاری

### مسیر واقعی سند

```
پیمانکار  ──ارسال──►  نظارت  ──تأیید──►  کارفرما  ──گردش داخلی──►  ابلاغ به پیمانکار
              │                │              │
       ارسال به نظارت   ورود به نظارت   ورود به کارفرما
```

### مراحل گردش کار داخلی (صورتجلسات جدید)

1. دریافت در دفتر کارفرما  
2. ارجاع به رئیس دفتر فنی  
3. بررسی کارشناس  
4. تأیید رئیس دفتر فنی  
5. تأیید مدیر سایت  
6. ابلاغ به پیمانکار  

### وضعیت‌ها

`در دست بررسی` · `در انتظار تأیید` · `تکمیل شده` · `لغو شده` · `بازگشت داده شده`

## نصب و اجرا

### پیش‌نیاز

- Python **3.11+**
- ویندوز (پیشنهادی برای محیط دفتر) یا لینوکس/مک برای توسعه

### نصب وابستگی‌ها

```bash
git clone https://github.com/Tahmoures54/Document-Tracking.git
cd Document-Tracking
pip install -r requirements.txt
```

### اجرا

```bash
python app.py
```

برای دیتابیس مشترک شبکه، طبق بخش «دیتابیس مشترک شبکه (چندکاربره)» از URL اتصال PostgreSQL با گزینه `--db-url` استفاده کنید. مسیر فایل SQLite فقط برای دیتابیس محلی است.
---

## ساخت فایل اجرایی (EXE)

### الف) از GitHub Actions (پیشنهادی)

1. مخزن → **Actions** → **Build Windows Executable**
2. **Run workflow**
3. دانلود Artifact به نام `DocumentTracking-Windows`

با زدن تگ نسخه، Release هم ساخته می‌شود:

```bash
git tag v3.1.0
git push origin v3.1.0
```

### ب) ساخت محلی

```bash
pip install -r requirements.txt
pyinstaller build.spec
# خروجی: dist/DocumentTracking.exe
```

یا همان دستور کامل داخل ورک‌فلو (بدون کنسول، با آیکون `app.ico`).

## دیتابیس مشترک شبکه (چندکاربره)

**حالت پیشنهادی برای استفاده هم‌زمان چند همکار: PostgreSQL روی یک رایانه سرور یا سرور شبکه.**
برنامه روی هر رایانه جداگانه نصب و اجرا می‌شود؛ اطلاعات همه کاربران در یک پایگاه داده مرکزی قرار می‌گیرد. برای اتصال چندرایانه‌ای از PostgreSQL استفاده کنید، نه بازکردن مستقیم یک فایل SQLite از مسیر اشتراکی.

### ۱) آماده‌سازی سرور
1. PostgreSQL را روی سرور شبکه نصب کنید و یک پایگاه داده، مثلاً `document_tracking`، بسازید.
2. برای برنامه یک حساب دیتابیس اختصاصی با مجوز اتصال و ایجاد/ویرایش جداول لازم بسازید.
3. دسترسی PostgreSQL و فایروال را به شبکه داخلی موردنیاز محدود کنید؛ پورت پیش‌فرض معمولاً `5432` است.
4. از پایگاه داده مرکزی به‌صورت منظم نسخه پشتیبان تهیه کنید.

### ۲) اتصال هر رایانه
نمونه آدرس اتصال (مقادیر نمونه را با اطلاعات سرور خود عوض کنید):

```text
postgresql+psycopg://doc_app:CHANGE_ME@192.168.1.10:5432/document_tracking
```

متغیر محیطی `DOCUMENT_TRACKING_DATABASE_URL` را تنظیم کنید، یا با آرگومان اجرا کنید:

```powershell
DocumentTracking.exe --db-url "postgresql+psycopg://doc_app:CHANGE_ME@192.168.1.10:5432/document_tracking"
```

برای اجرای نسخه پایتونی:

```bash
python app.py --db-url "postgresql+psycopg://doc_app:CHANGE_ME@192.168.1.10:5432/document_tracking"
```

تنظیم اتصال، قفل اجرای برنامه و گزارش خطا در فضای محلی هر کاربر ذخیره می‌شوند؛ اجرای برنامه روی یک رایانه، اجرای همکاران را مسدود نمی‌کند.

### ۳) دسترسی و داده‌های قبلی
- دسترسی شبکه، مجوز حساب PostgreSQL و حساب کاربری برنامه بر دسترسی اثر می‌گذارند.
- نقش‌های فعلی برنامه حفظ شده‌اند تا سوابق ممیزی و هویت ثبت‌کننده از بین نرود.
- در اولین اتصال به دیتابیس خالی، جداول لازم ساخته و حساب پیش‌فرض `admin/admin` ایجاد می‌شود؛ رمز را بلافاصله تغییر دهید.
- **داده‌های SQLite قبلی خودکار منتقل نمی‌شوند.** پیش از استفاده عملیاتی، داده‌ها را با ابزار انتقال مناسب منتقل و تعداد رکوردها را کنترل کنید.
- SQLite برای استفاده تک‌رایانه‌ای و آزمایش محلی همچنان پشتیبانی می‌شود؛ فایل SQLite را برای چند نویسنده هم‌زمان روی پوشه اشتراکی شبکه قرار ندهید.

## اسکن مدارک

مسیر پیش‌فرض شبکه:

```text
\\192.168.200.6\technical office\_MOM\_Scan
```

قابل تغییر با:

- متغیر محیطی `MOM_SCAN_PATH`
- یا تنظیمات داخل برنامه (`get_scan_path()`)

پسوندهای پشتیبانی‌شده: `.pdf` `.png` `.jpg` `.jpeg` `.tif` `.tiff`

نام فایل باید با **شماره صورتجلسه** یکی باشد؛ مثال: صورتجلسه `1404-025` → فایل `1404-025.pdf`

## گزارش‌ها

| نوع | نحوه |
|-----|------|
| گزارش گردش کار یک پرونده | از دیالوگ گردش کار |
| گزارش فیلتر شماره صورتجلسه | فیلد «شماره صورتجلسه» + دکمه **گزارش شماره** |
| خروجی اکسل | دکمه خروجی در پنجره اصلی |
| نمودار آماری | دکمه نمودار (در صورت نصب matplotlib) |

گزارش شماره شامل: **محل کار**، **روز مانده تا مهلت**، **موضوع**، **پیمانکار** و خلاصه بر اساس موقعیت است و به‌صورت HTML در پوشه `reports` ذخیره می‌شود.
