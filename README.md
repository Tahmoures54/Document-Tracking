## معرفی

این سامانه به تیم‌های دفتر فنی کمک می‌کند تا:

- صورتجلسات را ثبت و بایگانی کنند
- مهلت انجام و تأخیرها را ببینند
- گردش کار داخلی (کارفرما → دفتر فنی → کارشناس → مدیر سایت → ابلاغ) را پیگیری کنند
- مسیر واقعی **پیمانکار → نظارت → کارفرما** را با تاریخ ثبت کنند
- مدارک اسکن‌شده را از پوشه شبکه پیدا و باز کنند
- گزارش HTML و خروجی اکسل بگیرند

رابط کاربری راست‌به‌چپ (RTL) و تاریخ‌ها به‌صورت شمسی (جلالی) نمایش داده می‌شوند.

## قابلیت‌های اصلی

| حوزه | توضیح |
|------|--------|
| **ثبت صورتجلسه** | شماره، موضوع، تاریخ‌ها، کارفرما/مشاور/پیمانکار، دیسیپلین، محل کار، اولویت |
| **مسیر نظارت** | تاریخ ارسال به نظارت، ورود به دفتر نظارت، ورود به کارفرما |
| **گردش کار ۶ مرحله‌ای** | دریافت کارفرما → ارجاع دفتر فنی → بررسی کارشناس → تأیید دفتر فنی → تأیید مدیر سایت → ابلاغ به پیمانکار |
| **ابلاغ = اتمام** | ثبت تاریخ ارسال به پیمانکار پرونده را تکمیل‌شده می‌کند |
| **هشدار شباهت** | جلوگیری نسبی از ثبت تکراری همان کار توسط پیمانکار (محل / نقشه) |
| **فیلتر شماره** | جستجوی حاوی (مثلاً `10`) + گزارش HTML |
| **اسکن شبکه** | پیدا کردن PDF/تصویر با نام برابر شماره صورتجلسه |
| **نقش و دسترسی** | admin / manager / editor / user / viewer |
| **حذف منطقی** | Soft-delete با حفظ سابقه |
| **لاگ ممیزی** | ثبت رویدادهای مهم (از جمله عبور از هشدار شباهت) |

## جریان کاری

### مسیر واقعی سند

```
پیمانکار  ──ارسال──►  نظارت  ──تأیید──►  کارفرما  ──گردش داخلی──►  ابلاغ به پیمانکار
              │                │              │
       ارسال به نظارت   ورود به نظارت   ورود به کارفرما
```

### مراحل گردش کار داخلی (صورتجلسات جدید)

1. دریافت در دفتر کارفرما  
2. ارجاع به رئیس دفتر فنی  
3. بررسی کارشناس  
4. تأیید رئیس دفتر فنی  
5. تأیید مدیر سایت  
6. ابلاغ به پیمانکار  

### وضعیت‌ها

`در دست بررسی` · `در انتظار تأیید` · `تکمیل شده` · `لغو شده` · `بازگشت داده شده`

## نصب و اجرا

### پیش‌نیاز

- Python **3.11+**
- ویندوز (پیشنهادی برای محیط دفتر) یا لینوکس/مک برای توسعه

### نصب وابستگی‌ها

```bash
git clone https://github.com/Tahmoures54/Document-Tracking.git
cd Document-Tracking
pip install -r requirements.txt
```

### اجرا

```bash
python app.py
```

مسیر دیتابیس سفارشی:

```bash
python app.py --db "\\SERVER\share\meetings.db"
```

## ساخت فایل اجرایی (EXE)

### الف) از GitHub Actions (پیشنهادی)

1. مخزن → **Actions** → **Build Windows Executable**
2. **Run workflow**
3. دانلود Artifact به نام `DocumentTracking-Windows`

با زدن تگ نسخه، Release هم ساخته می‌شود:

```bash
git tag v3.1.0
git push origin v3.1.0
```

### ب) ساخت محلی

```bash
pip install -r requirements.txt
pyinstaller build.spec
# خروجی: dist/DocumentTracking.exe
```

یا همان دستور کامل داخل ورک‌فلو (بدون کنسول، با آیکون `app.ico`).

## دیتابیس شبکه

- موتور: **SQLite** (حالت WAL)
- فایل معمولاً روی پوشه اشتراکی شبکه قرار می‌گیرد
- چند کلاینت می‌توانند همزمان به همان فایل وصل شوند
- **دسترسی به فایل دیتابیس** با مجوز پوشه شبکه کنترل می‌شود (رمز جدا روی فایل DB نیست)
- رمز ورود برنامه فقط برای نقش و دسترسی داخل اپلیکیشن است

پیشنهاد عملی:

1. یک مسیر شبکه ثابت برای `meetings.db` تعیین کنید  
2. روی همه کلاینت‌ها با `--db` یا از تنظیمات داخل برنامه همان مسیر را بگذارید  
3. پشتیبان‌گیری دوره‌ای از فایل `.db` را فراموش نکنید

## اسکن مدارک

مسیر پیش‌فرض شبکه:

```text
\\192.168.200.6\technical office\_MOM\_Scan
```

قابل تغییر با:

- متغیر محیطی `MOM_SCAN_PATH`
- یا تنظیمات داخل برنامه (`get_scan_path()`)

پسوندهای پشتیبانی‌شده: `.pdf` `.png` `.jpg` `.jpeg` `.tif` `.tiff`

نام فایل باید با **شماره صورتجلسه** یکی باشد؛ مثال: صورتجلسه `1404-025` → فایل `1404-025.pdf`

## گزارش‌ها

| نوع | نحوه |
|-----|------|
| گزارش گردش کار یک پرونده | از دیالوگ گردش کار |
| گزارش فیلتر شماره صورتجلسه | فیلد «شماره صورتجلسه» + دکمه **گزارش شماره** |
| خروجی اکسل | دکمه خروجی در پنجره اصلی |
| نمودار آماری | دکمه نمودار (در صورت نصب matplotlib) |

گزارش شماره شامل: **محل کار**، **روز مانده تا مهلت**، **موضوع**، **پیمانکار** و خلاصه بر اساس موقعیت است و به‌صورت HTML در پوشه `reports` ذخیره می‌شود.
